# Arbitrage Lab · MVP

Локальное приложение для исследования Polymarket ↔ Limitless: **реальные котировки, виртуальные деньги**, интерфейс, симуляция заявок, P&L и подробная диагностика. Bybit-балансировка моделируется. Поля подключений — заглушки; реальные ключи не нужны и не сохраняются.

[Аудит логики, исправления и измерения](docs/project-audit-2026-10-17.md). [Профили $200/$500 и параметры стратегии](docs/strategy-settings.md). Прибыльность на реальных рынках ещё не подтверждена; положительный спред не гарантирует исполнение обеих сторон и совместимые выплаты.

## Открыть приложение

**http://127.0.0.1:4317**

Полный сброс локальных виртуальных сессий с архивированием истории и восстановлением настроек по умолчанию: `npm.cmd run reset:local`. Открытые тестовые позиции сохраняются в архиве, а новая сессия начинает с $100 на площадку и выключенной торговлей. Подробно о параметрах, порядке теста и примерах для разных сумм: [docs/strategy-settings.md](docs/strategy-settings.md).

Из PowerShell в D:/arbitrage:

~~~powershell
npm.cmd ci
npm.cmd run check
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/start-local.ps1
~~~

Скрипт запускает сервер в фоне со своим сборщиком данных. Для запуска в терминале: npm.cmd start. Перезагрузка компьютера не настраивается автоматически.

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/status-local.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/stop-local.ps1
~~~

ExecutionPolicy Bypass относится только к запускаемому процессу PowerShell, системные настройки не меняются. Компьютер и интернет должны оставаться доступны. Не запускать старый observe одновременно с MVP на одном каталоге данных.

## Быстрая проверка

1. В верхнем переключателе выбрать **«Демо-сценарии»**.
2. Нажать **«Запустить сценарий»**: примерно через 16 секунд пройдёт полный цикл до виртуальной выплаты.
3. В **«Сделках»** проверить стоимость, комиссии, остатки и реализованный P&L.
4. Проверить отдельные сценарии частичного исполнения, отказа, задержки и несовместимого расчёта.
5. В **«Журнале событий»** скачать сессию и архивы торговых событий.

Журнал MVP сохраняет заявки, исполнения, комиссии, закрытия и результаты сделок, настройки и критические ошибки. Потоки REST/WS, фоновые оценки и периодические снимки капитала не архивируются. Текущее состояние и график капитала сохраняются отдельно для восстановления.

Демо использует отдельные синтетические данные и отдельный баланс. Его результаты не оценивают прибыльность рынка. В режиме **«Реальные котировки»** сделки возможны только после проверки конкретных правил пары и появления подходящего спреда. По умолчанию оба виртуальных счёта начинают с $100 на площадку; новые входы на старте поставлены на паузу.

## Возможности

- Обзор капитала, график, реализованный и нереализованный P&L, комиссии и распределение средств.
- Публичные REST/WS двух площадок, все найденные совместимые активные бинарные CLOB-рынки без ограничения срока и количества пар. Обход каталогов идёт до конца пагинации, полнота поиска показана в интерфейсе.
- Поиск кандидатов, сравнение правил и проверка по хешам/сроку действия.
- Резервирование средств, задержка до исполнения по будущему снимку, limit/FAK, частичные fills, отказы и аварийная продажа по bid.
- Ограничения бюджета, резерва, открытых сделок и реализованного убытка.
- Отдельное подтверждение окончательной выплаты каждой площадки; ожидание при неподдержанном статусе.
- Виртуальный маршрут Polygon → Bybit → Base и обратно с депозитом, выводом, транзитом и комиссией.
- Сохранение состояния, write-ahead журнал и восстановление после перезапуска без повторного списания.
- Полные ответы публичных REST и WS для наблюдаемых рынков, исходные стаканы, исполнения, параметры и ошибки в сжатом архиве.
- Экспорт JSON/CSV и управление параметрами в интерфейсе.
- Подготовленные, отключённые от реальной торговли поля API/RPC.

## Стек и данные

TypeScript / Node.js 24 LTS, decimal.js, PostgreSQL опционально, HTML/CSS/JS интерфейс без внешних CDN. Для локального запуска БД не обязательна: используются JSON-состояние, транзакционный JSONL и gzip JSONL диагностики. Всё создаётся в data/, исключённом из Git. Файл .env не коммитится.

Диагностика ограничена AUDIT_MAX_MB (по умолчанию 2048 МБ); переполнение останавливает новые операции и сбор, а не заполняет диск. Старые файлы не удаляются автоматически. UI показывает последние события; полные архивы доступны отдельно.

## Проверки

~~~powershell
npm.cmd run check
npm.cmd run test:ui
~~~

Браузерный тест использует установленный Microsoft Edge, отдельный временный каталог и синтетические данные. Результаты проверки и ограничения: [docs/validation.md](docs/validation.md).

Самостоятельные инструменты доступны: npm.cmd run scan, npm.cmd run observe, npm.cmd run benchmark -- --samples 20. Замер публичных HTTP-запросов не измеряет исполнение ордеров.
