# Локальный запуск и подготовка VPS

Текущий этап — локальный пользовательский тест. На VPS команды не выполнялись. Сервер с Amnezia: 2 vCPU, 2 ГБ RAM, 30 ГБ диска, Ubuntu 20.04. Полный raw-архив требует контроля диска; фактическую нагрузку нужно измерить.

## Сейчас: Windows

~~~powershell
npm.cmd ci
npm.cmd run check
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/start-local.ps1
~~~

Открыть http://127.0.0.1:4317. Полный сценарий — [mvp.md](mvp.md). Данные остаются в data/. Для остановки используется scripts/stop-local.ps1; завершать все процессы Node.js не требуется.

## Перед будущим размещением

Проверить SSH по отдельному ключу, доступ к консоли провайдера, свободную память/диск и существующие контейнеры. Не передавать пароль или приватный ключ в чат/репозиторий.

~~~bash
uname -a
cat /etc/os-release
free -h
df -h
docker version
docker compose version
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
~~~

Не менять Docker daemon, firewall, IP forwarding, сетевые интерфейсы или контейнеры Amnezia. Обновление ОС с VPN требует отдельной резервной копии. Для нового сервера предпочтительна Ubuntu 24.04 LTS.

## Подготовленный Docker-запуск

После локального теста передать исходники в отдельную папку, например /opt/arbitrage-lab, исключив node_modules, .git, данные и секреты. При переносе виртуального портфеля отдельно сохранить весь data/ и проверить восстановление до продолжения эксперимента.

~~~bash
cp .env.example .env
chmod 600 .env
~~~

В .env локально на сервере задать уникальный POSTGRES_PASSWORD. Настройки БД передаются отдельными PG* полями. Если пароль содержит $, использовать одинарные кавычки, чтобы Compose не интерполировал его.

~~~bash
docker compose config --quiet
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=100 observer
~~~

Контейнер приложения запускает dist/server.js и публичный сканер. PostgreSQL не публикует порт. UI публикуется **только** на loopback хоста: 127.0.0.1:4317. Для просмотра с компьютера:

~~~bash
ssh -N -L 4317:127.0.0.1:4317 USER@SERVER
~~~

Открыть http://127.0.0.1:4317 на компьютере. Публичное размещение UI без отдельной аутентификации не предусмотрено. Проверка Host/Origin и локальный токен не заменяют пользовательскую аутентификацию для открытого интернета.

Приложение работает от пользователя node, конфигурация репозитория доступна на чтение, динамические проверки пар сохраняются в том данных. Пределы контейнеров: до 768 МБ для приложения и 384 МБ для БД. Проверять docker stats, free -h, задержки и рост архива.

~~~bash
docker compose stop
~~~

Не использовать docker system prune, удаление томов или остановку всех контейнеров. Данные БД, том наблюдений и настройки сохранять перед переносом. Unhealthy сам по себе не перезапускает контейнер; завершение с ошибкой имеет до трёх автоматических перезапусков. Новые paper-входы после перезапуска всегда на паузе.

Docker Compose синтаксически проверен. Полный Docker runtime пока не проверен: локальный Docker Engine не запущен.

## Архивирование

Сохранять audit-архив, paper WAL, state.json, sessions и reviews вне VPS. Использовать pg_dump, если включён PostgreSQL, и проверять восстановление. Лимит диагностики по умолчанию — 2 ГБ, WAL — 256 МБ на paper-счёт; автоматического удаления нет.

Для сравнения хостов запускать npm run benchmark -- --samples 20 в отдельном каталоге, когда основной процесс остановлен. Это замер публичного HTTP-ответа, не исполнения ордеров.
