# Проверка MVP v0.2 — 17 октября 2026

Проверка выполнена локально на Windows с Node.js 24.14.0. На VPS команды не выполнялись. Реальные аккаунты, деньги, торговые ключи и переводы не использовались.

## Автоматические проверки

- npm.cmd run check: строгая проверка TypeScript, синтаксис интерфейса, **49 тестов в 8 файлах**, сборка — успешно.
- npm.cmd run test:ui: headless Microsoft Edge — успешно. Проверены dashboard, переключение источника, полный демо-цикл и положительный реализованный P&L, детали сделки, пауза, сохранение параметров, заглушки подключений, журнал/архивы, отсутствие горизонтального переполнения на мобильной ширине.
- В браузерном тесте введённое тестовое значение API-ключа не попало ни в один POST и очищено кнопкой проверки макета. JavaScript-ошибок не было.
- Синтаксис Docker Compose проверен. Полный Docker runtime и PostgreSQL в контейнерах не запускались: локальный Docker Engine не запущен.
- При установке зависимостей npm audit сообщил 0 известных уязвимостей. Версии зафиксированы в package-lock.json.

## Что проверяют тесты

Исходные проверки: сортировка/глубина стаканов, микроконтракты и NO-инверсия Limitless, комиссии в контрактах, цена-зависимые комиссии Polymarket, одинаковое чистое покрытие, бюджет и минимум, устаревшие данные/рассогласование, проверка правил и изменение хеша, WS-дельты/версии, cursor/page pagination, неполное покрытие, JSONL и предел диска.

Новые проверки MVP:

- резервирование без преждевременного списания, задержка и только будущий снимок;
- один вход на событие, ограничение количества позиций и доступного баланса;
- независимые окончательные результаты площадок без повторной выплаты;
- отрицательный результат несовместимых выплат;
- частичное исполнение и отказ второй стороны с аварийной продажей по bid;
- сохранение непокрытой позиции при отсутствии ликвидности выхода;
- ожидание задержанного расчёта и отклонение старых/спорных статусов;
- отмена очереди при паузе, отмена при изменении правил, лимит реализованного убытка;
- виртуальный транзит и однократная комиссия балансировки;
- восстановление более нового WAL относительно checkpoint и ремонт неполного хвоста;
- полные gzip-записи, маскирование секретов, сохранение числового seed модели, жёсткий предел диагностики;
- локальные HTTP-ограничения Host/Origin/токена, запрет неизвестных credential-полей, отсутствие endpoint реального вывода и изоляция live/demo.

## Живые публичные данные

В проверенном запуске MVP каталог содержал **128 пар-кандидатов**, в потоке — 10 пар. Оба WebSocket были подключены, без ошибок разбора. За один из проверочных интервалов получено более 12 000 сообщений Polymarket и более 1 300 сообщений Limitless; записано более 14 000 диагностических событий, очередь записи успевала освобождаться, ошибок архива не было.

Каталог Polymarket ограничивается MAX_PAGES. Наличие 128 кандидатов не означает 128 одинаковых контрактов или прибыльных возможностей. Правила реальных пар не одобрены автоматически, новые виртуальные входы оставлены на паузе. Пользовательский paper-счёт реальных котировок начинает с $200 и нулевого P&L.

Первый запуск прошлой версии сканера с неполной выборкой обнаруживал 1 925 рынков Polymarket и 196 рынков Limitless после фильтрации/поиска по внешним ссылкам. Количество рынков меняется во времени; оно не используется как утверждение о полном охвате.

## Проверка интерфейса

Снимки локального браузерного теста сохраняются в data/mvp-desktop.png и data/mvp-mobile.png. Рабочий интерфейс текущего приложения — http://127.0.0.1:4317. Браузерные тесты используют отдельный временный каталог: тестовая прибыль не переносится на счёт реальных котировок.

## Не проверено этим этапом

Непрерывная работа в течение недель, реальное исполнение, точная очередь matching engine, фактические индивидуальные комиссии/лимиты, полный набор видов споров, PostgreSQL/Docker runtime и работа на VPS. Вероятности отказов/частичных fills — допущения модели. Следующий этап — пользовательский локальный тест и анализ логов; затем отдельное размещение на VPS.
