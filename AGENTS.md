# Инструкции для работы в проекте

- Отвечать по-русски, максимально кратко и по существу. Работать до результата, не запрашивать повторно уже данное разрешение.
- Для продолжения из нового чата сначала прочитать `CHAT_CONTEXT.md`, затем `Plan.md`. Остальные документы и исходники открывать только по задаче.
- Проект: Node.js 24 + TypeScript, Windows PowerShell, `D:\arbitrage`. В Windows использовать `npm.cmd`. Интерфейс: http://127.0.0.1:4317.
- Сейчас только виртуальная торговля на публичных котировках. Реальные заявки, подключения кошельков и переводы не реализованы. Не подменять исполнение оценкой по стакану и не обещать гарантированную прибыль.
- Сохранять сессии, баланс, историю, пользовательские настройки. Не сбрасывать данные и не менять задержку 400 мс ради появления сделок. Не отключать проверки риска/глубины/цен/правил без обоснованного изменения задачи.
- На VPS работает отдельный сборщик диагностики, полного приложения и UI там нет. Сохранять Amnezia VPN, сетевые настройки и основную локальную сессию.
- Не читать/выводить секреты, `.env`, приватные ключи. Не переносить пароль из переписки в файлы. Ограниченный SSH-ключ отчётов не даёт оболочку или туннель.
- Экономить контекст: сначала `rg`, ограниченные фрагменты и агрегаты. Не читать целиком CSV/JSONL/архивы, `node_modules`, `dist`, большие отчёты. Выводить нужные поля и несколько релевантных сделок.
- Обычные журналы — сделки, настройки и критические ошибки; не возвращать посекундный raw/WS/REST/equity-архив. Исключение — ограниченные окна специальной диагностики.
- Изменения кода проверять соразмерными тестами; перед завершением существенных изменений `npm.cmd run check`, для UI также `npm.cmd run test:ui`. Для одной документации достаточно проверки ссылок и содержания.
- Исторические результаты проверок и снимки состояния не считать текущими. После значимых изменений кратко обновлять `CHAT_CONTEXT.md` и `Plan.md`, не дублируя историю.
